## Phase 1 — Audit quotes (verbatim from AUDIT_2026-05-03.md)

### U5 (lines 68-72)

> **U5. `/post-job` silently redirects pre-trial employers to subscription page**
> **Where:** Employer without active subscription navigating to `/post-job`. Barry was redirected from `/post-job` straight to `/dashboard/subscription` showing "Get started / 3-month free trial" + £99/month plan card. Screenshot `06-post-job-1280.png`.
> **Why it matters:** Functionally correct (gate before posting). UX issue: there's **no banner explaining why they were redirected**. A first-time user clicks "Post Job" in the sidebar, lands on a subscription page, no explanation. Could be misread as a bug.
> **Suggested fix:** Either (a) add a banner "Start your trial to post your first job" at the top of `/dashboard/subscription` when redirected from `/post-job`, or (b) intercept the click in the sidebar and show an inline modal "Start trial first" rather than a silent redirect.
> **Effort:** S.

### U8 (lines 86-91)

> **U8. Pipeline view shows only 3 status columns (REVIEWING / SHORTLISTED / INTERVIEW)**
> **Where:** `/pipeline` for new employer. Screenshot `09-pipeline-empty-1280.png`.
> **What:** Kanban-style page renders only 3 columns visible at 1280px. Dashboard pipeline widget shows 6 (APPLIED, REVIEWING, SHORTLISTED, INTERVIEW, OFFERED, HIRED).
> **Why it matters:** Inconsistency between dashboard pipeline widget and the dedicated pipeline page is jarring. Are APPLIED/OFFERED/HIRED hidden behind horizontal scroll, or genuinely missing? Either way candidates in those stages disappear from the pipeline view.
> **Suggested fix:** Verify whether columns are scrolled off-canvas (then add scroll affordances) or genuinely missing (then add them).
> **Effort:** S to verify, S-M to fix depending.

## U8 — Already fixed, verified live on production

### Source state (current)

`app/pipeline/page.tsx:22-29`
```ts
const STAGES = [
  { id: 'reviewing',   label: 'Reviewing',   color: '#3b82f6' },
  { id: 'shortlisted', label: 'Shortlisted', color: '#8b5cf6' },
  { id: 'interview',   label: 'Interview',   color: '#06b6d4' },
  { id: 'offered',     label: 'Offered',     color: '#10b981' },
  { id: 'hired',       label: 'Hired',       color: '#16a34a' },
  { id: 'rejected',    label: 'Declined',    color: '#6B7280' },
]
```
6 stages defined — matches the audit's expected count. Note: "Applied" is the implicit initial state (`job_applications.status = 'pending'` on creation, immediately surfaces in the Reviewing column on first employer view), not a separate column. This is by design.

### Git history of the U8 fix line

```

d2ff61b7  ui: pipeline fits the viewport — six columns, no horizontal scroll
```

The U8 line was iterated four times after the audit. Final layout choice: keep all 6 columns visible, allow horizontal scroll on narrow desktop, switch to a 3×2 grid on mobile. The 29d268f2 message says "revert U8" — that reverts the *"fit all columns in viewport at any width"* approach in favour of horizontal scroll + mobile grid.

### Audit's required fix delivered

The audit asked: *"Verify whether columns are scrolled off-canvas (then add scroll affordances) or genuinely missing (then add them)."*

Both halves of the OR are addressed:
- Desktop: scrolled off-canvas at narrow widths — `.board` CSS uses `overflow-x: auto` with a thin scrollbar (`scrollbar-width: thin; scrollbar-color: #cbd5e1 transparent`) per the current `pipeline/page.module.css`, which IS a scroll affordance.
- Mobile: layout is 3×2 grid — no scroll required, all 6 stages visible.
